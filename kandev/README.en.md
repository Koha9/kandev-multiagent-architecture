# Kandev deployment

[中文](README.md) | **English**

Deploys the [multi-agent development workflow](../docs/workflow.en.md) to any Kandev workspace. To have an agent deploy and verify it for you, see [../AGENTS.md](../AGENTS.md) (Chinese).

## Files

| File | Purpose |
|---|---|
| `build_workflows.py` | The single source of configuration: structure and prompts of the three workflows, plus the `apply` / `dump` commands |
| `check_docs.py` | Self-check: whether prompts.md is up to date, links, step names, template paths, version number, stage regression tests. Run it after changing the workflow and before deploying |
| `stage.py` | Stage classification for the guard: works out from Kandev state whom each task is "waiting on", and generates `agents/guard/stage.md` and alerts |
| `tests/` | Offline regression tests for `stage.py` (`python kandev/tests/test_stage.py`) |
| `verify_export.py` | Exports the deployed workflows, prints each step's configuration for checking, and writes a copy with machine-specific IDs removed to `export/` |
| `export/` | Example workflows: the three workflows exported from a real deployment, see [export/README.en.md](export/README.en.md) |
| `handoff/` | Handoff prompts for work the external MCP cannot do and that must be handed to an agent inside Kandev |
| `profiles.example.json` | Example format for role → agent profile ID |
| `profiles.local.json` | The profile IDs actually used on this machine (maintained per machine, not committed) |
| `kandev_ids.json` | Generated by `apply`: the IDs of each workflow and step (different on every machine, not committed) |

## Prerequisites

- Kandev is running and the external MCP endpoint is reachable (default `http://localhost:38429/mcp`, change it with `--url`).
- Python 3. The scripts use only the standard library; no dependencies to install.
- One agent profile prepared for each of the 5 required roles (pm, auditor, developer, reviewer, mechanical); the optional roles module, module_auditor and plan_auditor default to pm, auditor and auditor respectively (see `profiles.example.json` and "Roles and profiles" in [docs/workflow.en.md](../docs/workflow.en.md)):
  - auditor and plan_auditor must differ from pm, module_auditor must differ from module, and reviewer must differ from developer.
  - Plan review (plan_auditor) has a small context and the biggest impact, so the strongest model fits; mechanical runs the merge gate, so use a coding model.
  - The mode should preferably be a permission mode that can run unattended.

## Deployment

Run in the `kandev/` directory (replace `python` with this machine's Python interpreter):

```
python check_docs.py
python build_workflows.py apply --workspace <workspace_id> --profiles profiles.local.json
python verify_export.py
```

- `apply` imports in the order W3 → W2 → W1 (each later workflow's prompts embed the step IDs of the earlier one). It first imports without profiles, then binds profiles step by step by ID, and finally writes out `kandev_ids.json`.
- **Workflows with the same name already exist**:
  - Same version: running `apply` again only syncs prompts and profiles; the structure is not changed.
  - Other version: add `--retire-existing`. The old version is renamed to "<name> (<old version>)", e.g. "(v3.1)", all its tasks are kept, and then the new version is imported. Projects in progress on the old version finish on the old workflow.
- **After changing prompts**: `python build_workflows.py dump --out ../docs/prompts.md`, then run `check_docs.py` again.
- After deploying, check it against "Verify the deployment" (验收部署, section B) in [AGENTS.md](../AGENTS.md).

## Guard automation

The external MCP cannot create automations, so the guard (one per workspace, covering all projects) has to be created by an agent inside Kandev:

1. Copy [handoff/guard-automation.md](handoff/guard-automation.md) (Chinese) to `guard-automation.local.md` in the same directory (already git-ignored), and replace the `{大写占位}` (uppercase placeholders) in it with this machine's values.
2. In any Kandev task, give the whole "handoff prompt" (交接 prompt) section of the copy to the agent to execute.

You can also create it manually in Kandev Settings → Automations: schedule `*/20 * * * *`, hidden run, a profile with a cheap model, concurrency 1; for the prompt, see the "Guard automation" (守护 automation) section at the end of [docs/prompts.md](../docs/prompts.md) (Chinese) (replace `<arch_root>` and `<python>` in it).

## Other manual parts

- **Repository settings**: Copy files, the worktree branch template, etc. are configured per project once they have been decided by the baseline module (raised through the pm when the user has to configure something).
