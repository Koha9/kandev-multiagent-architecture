# 管理流程
workspace: 主workspace中单独新建管理文件夹进行分层管理和记录。
lifecycle:
管理整个开发从开始到结束的全过程。
验收调查agent管理范围仅限于所担当的对应模块。
## 开发流程制定
	明确开发目标，将抽象目标具象化为开发模块。
	制定开发环境，配置开发工具，明确开发规范。
	首次执行：将开发模块拆分task任务发送给task分发agent。
## task分发(分发agent)
	整理分析可分发task，将task进行分类和优先级排序，发送给`开发流程`。
## 接收上报(验收调查agent)
	结果接收，进行调查并记录相关信息到管理workspace中。(不记录原始代码)
	需要的时候可以和`开发agent`or`审核agent`进行沟通？
## 完成
	全部任务完成。

# 开发流程
workspace: task指定workspace。
lifecycle: 每个 task 从接收、开发、审查到完成的生命周期。
## 开发(开发agent)
	接收任务并执行开发。
## 审查(审核agent)->
	对开发结果进行外部审核，检查是否与任务契约和验收标准一致，内部具体实现不进行干预。
### 上报(审核agent)->
	状况判断：
	- 1.如果是小问题的话，直接反馈给开发进行修改。
	- 2.如果是方向性或者关联性问题，提出修改建议并反馈给xxxx进行调整。
	- 3.没有问题，上报结果给xxx完成。
## 完成
	任务完成，归档相关信息。

# 上下文检测守护
短上下文
## 目的
判断某个session或者task的上下文过长，激发压缩流程或者task调整流程。
## 执行激发条件
- 30分钟执行一次？
- 某session 窗口用量超过阈值执行？
## 位置
每个task保留一位？
整体监控所有session？
## 压缩或调整流程
如何开始上下文或者task调整？
`开发流程`的话上报给管理流程
