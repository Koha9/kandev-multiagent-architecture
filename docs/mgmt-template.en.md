# Management directory template (mgmt-template)

[中文](../mgmt-template/README.md) | **English**

> English translation of [mgmt-template/README.md](../mgmt-template/README.md), for reading only. The [mgmt-template/](../mgmt-template/) directory is copied as a whole into each project's management directory, and its README (Chinese) becomes `<project> 管理 workspace`: the map and recovery protocol that every agent reads first when recovering context. It is kept to 60 lines or fewer. The templates and role cards it refers to are in Chinese; for the design behind them see [mgmt-workspace.en.md](mgmt-workspace.en.md).

## Recovery protocol (any agent, any time)

1. Confirm your scope from the `[TASK v1]` header of the task description.
2. Read `roles/<role>.md`.
3. Read your own NOW:
   - Management roles: `agents/<scope>/NOW.md` (replace the colon in the scope with a hyphen, e.g. `mod:auth` maps to `agents/mod-auth/`)
   - Developer: Kandev task doc `now`
   - Reviewer, plan reviewer, module auditor, guard: no NOW, start from scratch
4. Handle "Unconfirmed intents (未确认的意图)": redo with the same idempotency key, or delete after confirming it is done.
5. Handle "Waiting on (等待中)": check the conversation for a reply; on timeout, resend or escalate per `protocol/message.md`.
6. Continue from item 1 of "Next steps (下一步)".

**Do not** dig through conversation history or read other agents' files or code in order to recover.

## Directory

| Path | Contents | Writer |
|---|---|---|
| `roles/` | role cards | read-only |
| `protocol/message.md` | message and handoff format | read-only |
| `project/charter.md` | verbatim requirements (R-n), goals, scope, modules, module boundaries (B-n), project acceptance criteria | pm |
| `project/attention.md` | items for the user: open questions (with recommended answers), items that cannot be verified | pm |
| `project/conventions.md` | collaboration conventions | pm |
| `project/environment.md` | environment, commands, smoke test, merge gate, shared files | baseline module agent (mod:baseline or mod:baseline-fix-<n>) |
| `project/registry.json` | ownership registry: who owns what | pm |
| `project/status.json` | global status | pm |
| `project/final-report.md` | project acceptance report | project auditor (audit); the "收尾" (Wrap-up) section is written by Final merge |
| `project/decisions/` | ADRs | pm |
| `agents/<scope>/` | NOW.md, journal.md | the agent itself |
| `agents/guard/stage.md` | who we are waiting on now (gates, permission requests, stuck tasks) | generated by `kandev/stage.py` |
| `modules/<module>/` | spec, interfaces, tasks.json | that module's agent |
| `modules/<module>/acceptance.md` | module acceptance records and fix items | that module's auditor (mod-audit:<module>) |
| `evidence/<task id>/` | UI screenshots | that task's developer |
| `quota/ledger.json` | quota ledger | written only by `tools/quota.py` |
| `tools/` | check_owns, check_tasks, quota, mgmt_precommit scripts | read-only |
| `agents/_template/`, `modules/_template/` | copy sources | do not change |

## Single writer

Each file has only the writer listed in the table above. To change someone else's file, message its owner.

## Finding the owner (ask whoever owns it)

1. Module or project level: look up `owns` in `project/registry.json`.
2. Task level: look up `owns` in `modules/<module>/tasks.json`.
3. Not found: ask your upstream manager "who owns this"; do not guess, and do not go looking yourself.

## Current phase

See `phase` in `project/status.json`. The run mode (attended / unattended) is in the `[TASK v1]` header of the pm task description.

## Record-keeping conventions

Take timestamps from the system clock; if the management directory is under git, only `git add` paths you own, and set `MGMT_SCOPE` when committing (hook in `tools/mgmt_precommit.py`); register temporary resources in your own NOW and clean them up after use.

Items for the user are in `project/attention.md`; who the system is waiting on now is in `agents/guard/stage.md`.
